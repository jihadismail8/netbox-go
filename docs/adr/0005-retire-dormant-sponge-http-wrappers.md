# Retire dormant Sponge HTTP wrappers before capability completion

The repository contains 118 template-identical per-resource handler delegates
under `netbox-backend/internal/handler/` and 118 matching top-level
`netbox-backend/internal/routers/*_router.go` files generated by Sponge. These
wrapper pairs are not used by the canonical HTTP runtime, contain no retained
handwritten behavior, and add a duplicate transport-shaped maintenance surface.

ADR 0004 normally retires a generated stack only after its replacement passes
the capability-completion gate. This decision accepts one narrower
source-hygiene exception: remove exactly those 118 dormant handler wrappers and
their 118 matching generated router wrappers before the deferred capabilities
complete. The exception is based on their template identity, lack of runtime
ownership, and absence of unique behavior; it is not based merely on a file
being generated or currently disabled.

## Scope

- Remove the 118 template-identical per-resource `.go` delegates that were
  present directly under `netbox-backend/internal/handler/`, excluding
  `auth.go` and `auth_test.go`.
- Remove their 118 matching generated files directly under
  `netbox-backend/internal/routers/` whose names end in `_router.go`.
- Retain `internal/handler/auth.go`, its tests, canonical handlers under
  `internal/adapters/rest/netbox/`, hand-owned router/composition code, and all
  nonmatching router files and subpackages.
- Retain the frozen models, DAOs, caches, services, per-table protobuf sources
  and generated protobuf code, and the separate direct-GORM DRF registry. They
  remain available for controlled reference or reuse while later Capability
  Profiles are developed, but remain runtime-disabled and unpublished.

This decision authorizes no other generated-file deletion. The enumerated set
is fixed to the 236 files present when this ADR was accepted; the path patterns
above do not authorize deleting future handwritten files that happen to match
a broad glob.

## Consequences

- An architecture regression test must fail if any retired wrapper path or its
  generated constructor/registration pattern reappears.
- Generation and maintenance commands must not recreate the retired wrapper
  pairs. Retained generated artifacts remain governed by ADR 0004 and must not
  receive handwritten behavior.
- The canonical runtime surface and the frozen DRF registry inventory do not
  change. This cleanup earns no compatibility tier, does not complete a
  Capability Profile, and does not justify a broader REST, gRPC, Vue, module,
  or production-readiness claim.
- Future capability work must still use typed handwritten domain,
  application, persistence-adapter, and transport-adapter owners. Retained
  lower legacy layers are reference inputs, not architectural precedent.
- Every other ADR 0004 retirement condition remains in force. In particular,
  no model, DAO, cache, service, protobuf, DRF-registry entry, or other
  displaced legacy path may be removed early by analogy with this exception.
- The focused architecture and package tests, deterministic inventories,
  frozen client/protobuf compilation, coverage policy, and full repository V0
  gate must remain green after the deletion.
