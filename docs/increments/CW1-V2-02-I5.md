## Required observable contract

### Create, replace, and update

| Field           | POST omitted                         | PUT omitted    | PATCH omitted | Explicit `null`                       | Explicit zero/blank                         |
| --------------- | ------------------------------------ | -------------- | ------------- | ------------------------------------- | ------------------------------------------- |
| `manufacturer`  | required error                       | required error | preserve      | reject: may not be null               | invalid identifier/choice rejected          |
| `model`         | required error                       | required error | preserve      | reject: may not be null               | blank rejected                              |
| `slug`          | required error                       | required error | preserve      | reject: may not be null               | blank rejected                              |
| `form_factor`   | reject through nonblank model check  | preserve       | preserve      | reject through non-null model check   | blank rejected; exact choices only          |
| `width`         | default `19`                         | preserve       | preserve      | reject through blank-choice path      | zero/blank rejected; `10/19/21/23` only     |
| `u_height`      | default `42`                         | preserve       | preserve      | reject: may not be null               | zero rejected; range `1..100`               |
| `starting_unit` | default `1`                          | preserve       | preserve      | reject: may not be null               | zero rejected; range `1..32767`             |
| `desc_units`    | default `false`                      | preserve       | preserve      | reject: may not be null               | explicit `false` persists                   |
| `description`   | default `""`                        | preserve       | preserve      | reject: may not be null               | blank clears; maximum 200 code points       |
| `comments`      | default `""`                        | preserve       | preserve      | reject: may not be null               | blank clears; no profile-specific max claim |

The `form_factor` asymmetry is intentional. The custom serializer declares it
`required=False`, `allow_blank=True`, and `allow_null=True`, but the RackType
model is nonblank, non-null, and has no explicit valid default. POST omission
therefore constructs an empty value and
reaches model validation as blank and fails; PUT omission preserves the loaded
value. The generated create request still marks it required so clients cannot
construct the known-invalid omitted form. The replace request does not mark it
required.

Additional scalar rules:

- `model`, `slug`, `description`, and `comments` trim surrounding whitespace;
  `form_factor` uses the pinned custom choice field and must not be trimmed;
- model and slug are limited to 100 Unicode code points;
- slug uses the pinned ASCII `^[-a-zA-Z0-9_]+$` grammar and is not generated;
- form factor accepts exactly `2-post-frame`, `4-post-frame`,
  `4-post-cabinet`, `wall-frame`, `wall-frame-vertical`, `wall-cabinet`, and
  `wall-cabinet-vertical`;
- width remains an integer choice on the owned contract; generic DRF
  string-to-integer coercion and alternate nested Manufacturer input forms are
  not promoted here;
- combined violations are returned once in deterministic field order without
  discarding valid sibling-field state;
- POST retains add permission and PUT/PATCH retain change permission; this
  increment uses authorized principals and does not expand the RBAC matrix;
- every mutation uses one application-owned PostgreSQL transaction;
  PUT/PATCH load with `GetForUpdate`; relationship resolution, candidate
  authorization, validation, persistence, the pre-existing untouched
  propagation call, and object-change recording share that transaction;
- validation rejection leaves RackType state, timestamps, repository mutation
  counts, propagation calls, and object-change count unchanged;
- a repository or first object-change-recorder failure after an attempted
  write rolls all durable RackType state and object changes back; and
- successful POST/PUT/PATCH against the I5 zero-referencing-Rack fixtures writes
  the intended RackType state and one RackType object change. The existing
  propagation implementation is untouched and unaccepted; I5 fixtures assert
  that no Rack row or Rack object-change record exists rather than exercising
  or claiming propagation semantics.

Generic numeric/string coercion, malformed UTF-8 behavior, exact framework
diagnostic multiplicity, empty PATCH, relationship-dictionary inputs, and
byte-exact errors beyond the field-scoped matrix are not claimed. PATCH
omission tests include a concrete sibling field.

### Contract metadata and generated OpenAPI

RackType metadata must add:

```json
"field_contracts": {
  "response": {
    "nullable_fields": ["created", "last_updated"]
  },
  "create": {
    "required_fields": ["manufacturer", "model", "slug", "form_factor"],
    "nullable_fields": [],
    "blank_fields": ["description", "comments"]
  },
  "replace": {
    "required_fields": ["manufacturer", "model", "slug"],
    "nullable_fields": [],
    "blank_fields": ["description", "comments"]
  },
  "update": {
    "required_fields": [],
    "nullable_fields": [],
    "blank_fields": ["description", "comments"]
  }
}
```

- The profile validator makes RackType operation metadata mandatory and
  rejects missing operations, undeclared/duplicate fields, invalid subsets,
  and response/write conflation.
- Generated OpenAPI replaces `RackTypeWrite` with `RackTypeCreate`,
  `RackTypeReplace`, and `RackTypeUpdate`; POST/PUT/PATCH reference the matching
  schema.
- Create requires manufacturer/model/slug/form factor; replace requires only
  manufacturer/model/slug; update requires none.
- All ten write fields are non-nullable; only description/comments are
  blankable. Request Manufacturer remains a non-null integer ID.
- Response Manufacturer is a non-null `ObjectReference`; every declared
  business response field is non-null, while `created` and `last_updated` are
  nullable.
- Generated files change only through owned metadata/generator inputs.

### REST, gRPC, traceability, and Vue

- REST preserves omitted/null/blank/zero/false/concrete states through the
  typed decoder and central error mapper. Any production decoder change is
  limited to the pinned custom-choice blank/null distinction.
- Existing optional protobuf scalars preserve omission and concrete zero/false.
  For PATCH, a FieldMask path with an absent optional value means explicit-null
  intent and reaches the same application validation. Unknown paths fail
  closed. Optional proto scalars cannot independently encode POST/PUT null; no
  protobuf regeneration or redesign is authorized.
- Traceability adds only an unresolved
  `unresolved-rack-type-scalar-presence` assessment and points only RackType
  create/replace/update operation rows to it. The RackType resource-contract
  row remains mapped to the pre-existing contradicted filter-name assessment;
  uniqueness, propagation, deletion, consumer, verification, and tier rows do
  not change.
- Vue types RackType response timestamps as `string | null`, preserves create
  defaults, and keeps manufacturer/model/slug/form factor required.
- Vue serializes only form-owned fields, preserves false/zero/blank/concrete,
  converts Manufacturer selection to its ID, and keeps a private normalized
  edit baseline so unchanged edits emit no scalar.
- Vue field metadata pins width/form-factor choices, height `1..100`, and
  starting unit `1..32767`. Field-scoped backend validation reaches the
  matching control; Vue does not own authorization or domain validity.
