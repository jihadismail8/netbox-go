## Required observable contract

### Create, replace, and update

| Field         | POST omitted    | PUT omitted    | PATCH omitted | Explicit `null` | Explicit blank/false/concrete                 |
| ------------- | --------------- | -------------- | ------------- | --------------- | --------------------------------------------- |
| `device_type` | required error  | required error | preserve      | reject          | positive numeric ID; same owner on update     |
| `name`        | required error  | required error | preserve      | reject          | blank reject; trim; max 64                    |
| `label`       | default `""`    | preserve       | preserve      | reject          | blank clears; trim; max 64                    |
| `type`        | required error  | required error | preserve      | reject          | exact nonblank pinned choice; do not trim     |
| `enabled`     | default `true`  | preserve       | preserve      | reject          | explicit `false` persists                     |
| `mgmt_only`   | default `false` | preserve       | preserve      | reject          | explicit `false` persists                     |
| `description` | default `""`    | preserve       | preserve      | reject          | blank clears; trim; max 200                   |

Additional scalar rules:

- DeviceType input stays inside the profile's positive numeric-ID envelope.
  Upstream nested dictionary, numeric-string, ModuleType-owner, and generic
  lookup forms are not promoted here.
- Within the active profile every InterfaceTemplate is DeviceType-owned.
  Although the upstream serializer declares `device_type` optional because it
  also supports excluded ModuleType ownership, omitted/null DeviceType is not
  a valid create or replacement in this slice.
- The existing DeviceType-owner immutability guard remains active: PUT must
  name the current DeviceType and PATCH omission preserves it. A different
  known DeviceType rejects without mutation. I8 exercises that containment but
  does not close the separate owner-immutability traceability rule.
- Name, label, and description use pinned DRF whitespace trimming and Unicode
  code-point length limits. Only label and description accept stored blank.
- `type` accepts the exact pinned 206-value `InterfaceTypeChoices` set. Choice
  input is scalar and untrimmed. The value `bridge` is an interface type; it
  does not promote the excluded bridge relationship or bridge behavior.
- Combined violations return once in deterministic owned-field order without
  discarding valid sibling-field intent.
- POST retains add permission and PUT/PATCH retain change permission; I8 uses
  authorized principals and does not expand the RBAC matrix.
- Every mutation uses one application-owned PostgreSQL transaction.
  Relationship resolution, authorization, normalization, validation,
  persistence, and exactly one typed InterfaceTemplate object change share
  that transaction.
- Validation rejection leaves state, timestamp, repository mutation count,
  and object-change count unchanged. Repository or recorder failure rolls all
  durable state and object changes back.
- Scalar fixtures contain no Devices or Interfaces. They prove no template
  snapshot, Device instantiation, non-retroactivity, bridge, cascade, or
  dependent-resource behavior.

Generic coercion, malformed UTF-8, byte-exact framework diagnostics, empty
PATCH, alternate ownership/relationship input, and diagnostic multiplicity
remain out of scope. PATCH omission tests include a concrete sibling field.

### Contract metadata and generated OpenAPI

InterfaceTemplate metadata must add:

```json
"field_contracts": {
  "response": {
    "nullable_fields": ["created", "last_updated"]
  },
  "create": {
    "required_fields": ["device_type", "name", "type"],
    "nullable_fields": [],
    "blank_fields": ["label", "description"]
  },
  "replace": {
    "required_fields": ["device_type", "name", "type"],
    "nullable_fields": [],
    "blank_fields": ["label", "description"]
  },
  "update": {
    "required_fields": [],
    "nullable_fields": [],
    "blank_fields": ["label", "description"]
  }
}
```

- The profile validator makes InterfaceTemplate operation metadata mandatory
  and rejects missing operations, undeclared or duplicate fields, invalid
  subsets, non-string blank fields, and request/response conflation.
- Generated OpenAPI replaces `InterfaceTemplateWrite` with
  `InterfaceTemplateCreate`, `InterfaceTemplateReplace`, and
  `InterfaceTemplateUpdate`; POST/PUT/PATCH reference their matching schema.
- Request DeviceType is a non-null `int64`; response DeviceType is a non-null
  `ObjectReference`. Request type is a scalar string; response type is a
  non-null `{value,label}` choice envelope.
- All seven request fields are non-null. Create and replace require
  DeviceType, name, and type; update requires none. Only label and description
  are blankable.
- Only created and last_updated are nullable in the declared response.
- Generated files change only through owned metadata/generator inputs and are
  never hand-edited. Generator source changes require a red resource-neutral
  regression proving a generic defect.

### REST, gRPC, traceability, and Vue

- REST preserves omitted/null/blank/false/concrete states through the typed
  decoder and central error mapper. A handler edit requires a red
  InterfaceTemplate decoder regression.
- gRPC optional fields preserve omission, blank, and false. For PATCH, a mask
  path with an absent optional value is explicit-null intent and all seven
  non-null fields reject through the shared application path. Unknown mask
  paths fail closed.
- Protobuf cannot encode POST/PUT explicit null and returns scalar choice
  values rather than REST choice envelopes. No protobuf edit/regeneration or
  T3 claim is authorized; exact REST remains authoritative.
- Traceability adds `unresolved-interface-template-scalar-presence` and remaps
  only `operation.dcim.interface-template.create`, `.replace`, and `.update`
  to it. Resource/list/get/delete, owner immutability, uniqueness,
  instantiation, non-retroactivity, bridge, applicability, verification,
  consumer, and tier rows remain unchanged.
- Vue types InterfaceTemplate `created` and `last_updated` as `string | null`,
  supplies create defaults `enabled: true` and `mgmt_only: false`, and retains
  required DeviceType/name/type metadata plus the exact interface-type list.
- Vue serializes only the seven owned fields, maps DeviceType selection to a
  numeric ID, preserves false/blank/concrete intent, and keeps a private
  normalized edit baseline. An unchanged edit emits `{}` and one dirty field
  emits one delta.
- The existing immutable-on-edit control remains. Explicit relationship null
  is preserved long enough for field-scoped backend validation; Vue does not
  own relationship validity, immutability, or RBAC.
- Field-scoped backend validation reaches the matching control through the
  real DynamicForm contract.
