## Authority and current gap

- [ADR 0003](../adr/0003-unified-authentication-and-authorization.md)
  requires gRPC bearer credentials to resolve through the shared identity and
  authorization path. It permits only narrow health, readiness, login, and
  CSRF entry points to remain public.
- The execution playbook's
  [SEC-002 rule](../IMPLEMENTATION_EXECUTION_PLAYBOOK.md#security-rules)
  independently limits public interfaces to health, readiness, login, and
  CSRF entry points that expose no Managed Object data.
- [I2](CW1-V1-02-I2.md) retained strict unary Bearer grammar, direct-peer
  source evaluation, shared application authentication, exact outcome mapping,
  and fail-closed unary method classification. It explicitly deferred Health
  Watch, reflection, and all stream authentication, including unknown-stream
  authentication. I5 proposes an explicit reviewed disposition of that
  residual rather than redefining it away: authenticate every registered
  protected stream, while treating grpc-go's native pre-auth rejection as the
  fail-closed outcome for an unregistered operation.
- The runtime currently registers exactly three streaming operations:
  `grpc.health.v1.Health/Watch`,
  `grpc.reflection.v1.ServerReflection/ServerReflectionInfo`, and
  `grpc.reflection.v1alpha.ServerReflection/ServerReflectionInfo`. The three
  canonical application services currently declare no streams.
- The production stream interceptor chain contains recovery, logging, and
  optional operational interceptors, but no identity interceptor. Health Watch
  and both reflection services therefore bypass bearer parsing, token
  lookup/touch, source restrictions, write scope, and Principal injection.
- grpc-go rejects an unregistered service or method before the stream chain.
  I5 preserves that credential-free native `Unimplemented` result and proves
  that no identity handler or store effect occurs. Installing an
  `UnknownServiceHandler` is forbidden because it would also alter
  unary-shaped unknown calls outside this stream-authentication increment.
- The existing application `AuthenticateToken` operation already owns unknown,
  revoked, expired, inactive-owner, source, touch-order, write-scope, and
  infrastructure outcomes. I5 needs no domain, application, persistence,
  schema, protobuf, REST, or Vue contract.

## Proposed policy for review

Authentication occurs once, before the stream handler starts and before any
message is received. An accepted stream receives one stream-start snapshot
Principal in a wrapped `grpc.ServerStream.Context()`. I5 neither mutates that
snapshot nor reauthenticates per message; revocation and other state changes
are enforced at the next RPC or stream establishment. This matches unary
request authentication while keeping long-lived in-flight behavior explicit.

| Stream class                                             | Public | Token safety | Required behavior                                                                                      |
| -------------------------------------------------------- | ------ | ------------ | ------------------------------------------------------------------------------------------------------ |
| `grpc.health.v1.Health/Watch`                            | yes    | n/a          | Bypass metadata parsing and store access; call the health handler without fabricating a Principal      |
| Reflection v1 `ServerReflectionInfo`                     | no     | read         | Require strict Bearer metadata; accept a valid read-only token; inject its Principal                   |
| Reflection v1alpha `ServerReflectionInfo`                | no     | read         | Require strict Bearer metadata; accept a valid read-only token; inject its Principal                   |
| Any other registered stream                              | no     | write        | Require strict Bearer metadata and deny read-only tokens before its handler                            |
| Malformed method-name/path rejection before RPC dispatch | n/a    | n/a          | Preserve grpc-go's native rejection; do not enter application authentication or a registered handler   |
| Unregistered service or method                           | n/a    | n/a          | Preserve native credential-free `Unimplemented`; zero identity lookup, touch, or stream-handler effect |

Health Watch is the only public stream because it is the streaming form of the
already-public operational health contract and exposes or mutates no Managed
Object. Reflection is not one of ADR 0003's public exceptions; it is therefore
an authenticated read. No method becomes safe because its name resembles
`Get` or `List`. Every registered stream not explicitly classified public or
read defaults to write.

No unknown-RPC handler is installed. Unregistered calls retain grpc-go's native
`Unimplemented` outcome regardless of missing, malformed, read-only, or
write-enabled credentials. This is fail-closed because no undeclared handler,
Managed Object data, or mutation is reachable, and it avoids token lookup or
touch on an undeclared path. Owner acceptance of the packet must explicitly
accept this native pre-auth rejection as I5's resolution of I2's deferred
unknown-stream-authentication row; otherwise that row remains open and the
packet cannot activate.

Public Health Watch ignores absent, valid, malformed, or duplicate
authorization metadata exactly as unary Health Check does. Every protected
stream accepts exactly the I2 grammar:

- exactly one `authorization` metadata value;
- ASCII case-insensitive `Bearer` scheme;
- one or more ASCII spaces after the scheme;
- one non-empty opaque credential consisting only of visible ASCII bytes; and
- no leading/trailing whitespace, embedded space, control byte, non-ASCII
  byte, alternate scheme, or duplicate value.

Malformed metadata stops before hashing, lookup, touch, peer evaluation, or
handler entry. The credential value never appears in a status, log, assertion
diagnostic, or retained artifact. A logger-capture regression must prove this
for public Health Watch, protected missing/malformed metadata, successful
reflection, credential failures, and unregistered-RPC rejection.

## Credential and effect matrix

The stream adapter passes the original stream context, opaque credential,
direct peer address, and reviewed read/write classification to the unchanged
application operation. The application clock and persistence ordering remain
owned by I1/I2.

| Protected-stream condition                       | gRPC result                                                              | Lookup/touch/handler effect                                             |
| ------------------------------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Missing or malformed metadata                    | `Unauthenticated`: `Authentication credentials were not provided.`       | zero lookup, zero touch, handler not called                             |
| Unknown or revoked token                         | `Unauthenticated`: `Authentication credentials were not provided.`       | one lookup, zero touch, handler not called                              |
| Expired token                                    | `Unauthenticated`: `Authentication credentials were not provided.`       | one lookup, baseline-due touch before expiry denial, handler not called |
| Inactive token owner                             | `Unauthenticated`: `Authentication credentials were not provided.`       | one lookup, baseline-due touch before owner denial, handler not called  |
| Restricted token with unavailable peer           | `Unauthenticated`: `Authentication credentials were not provided.`       | one lookup, baseline-due touch before source denial, handler not called |
| Restricted token from denied peer                | `Unauthenticated`: `Authentication credentials were not provided.`       | one lookup, baseline-due touch before source denial, handler not called |
| Read-only token on reflection                    | success                                                                  | one lookup, due touch if required, exact Principal reaches handler      |
| Read-only token on another registered stream     | `PermissionDenied`: `You do not have permission to perform this action.` | one lookup, due touch before scope denial, handler not called           |
| Write-enabled token on another registered stream | success to its registered handler                                        | one lookup, due touch if required, exact Principal reaches handler      |
| Lookup or touch infrastructure failure           | `Internal`: `An internal error occurred.`                                | exact attempted effects; handler not called; backend cause is concealed |

Direct peer addressing remains the bounded I2 behavior. Trusted-proxy and
forwarded-client-source policy is a later child and must not be smuggled into
I5. An unrestricted token ignores an absent or malformed peer; a restricted
token fails closed through the unchanged application result.

## Proposed implementation shape

After activation, make only this vertical change:

1. In the gRPC identity adapter, extract a private shared bearer-authentication
   helper from the unary interceptor without changing unary behavior.
2. Add `StreamAuthenticator(*identity.Service)` with explicit public/read
   classification and default-write behavior.
3. Add a private `grpc.ServerStream` wrapper that delegates every stream method
   and overrides only `Context()` with `domain.WithPrincipal`.
4. Insert the identity stream interceptor immediately after stream recovery and
   before logging, matching the unary security ordering.
5. Preserve grpc-go's native unregistered-service and unregistered-method
   rejection without installing an unknown-service handler.
6. Keep runtime service registration unchanged: Identity, DCIM, IPAM, Health,
   and reflection v1/v1alpha only.

No new application port, transaction, store call, table, migration, generated
contract, public route, or frontend behavior is permitted.

The retained red observations must show all of these intended gaps:

- reflection v1 and v1alpha currently reach their handlers anonymously;
- the production stream chain never injects a Principal;
- protected stream metadata never enters the strict I2 parser;
- token outcome, source, touch, and write-scope semantics are not applied;
- valid read-only reflection cannot be distinguished from other registered
  write-classified streams at the authentication boundary.

The native-dispatch-rejection and logger-capture tests are green-preserving
regression boundaries, not red gaps. The first must prove native
`Unimplemented` for unregistered services and known-service/unknown-method
calls made with both unary and bidi client shapes, plus grpc-go's native
rejection for a malformed method name/path, with missing, malformed, read-only,
and write-enabled credentials. Identity lookup, touch, and registered handlers
must remain untouched. It must not assert a generic unary/stream client-shape
bypass for a registered method: the registered server descriptor chooses that
method's unary or stream path. The second must capture the server logs for the
public, protected-success, protected-failure, and unregistered cases above and
prove that no Bearer credential or metadata map is rendered.

The adapter and runtime Health Watch tests are also green-preserving
regressions. Runtime composition tests must remain non-parallel because the
configuration and logger are process globals. Each runtime fixture must call
`config.Set(&config.Config{})` before `grpcServer.setOptions()`, give every
`bufconn` RPC and stream a deadline, drive deferred stream errors through
`Send` or `Recv` rather than assuming `NewStream` returns them, cancel and
drain Health Watch before stopping the server, and leave no goroutine behind.
The logger proof must be nonvacuous: public Health Watch and successful
reflection must create stream-log entries, while protected authentication
failures and native dispatch rejections must create none because they stop
before `StreamServerLog`; the complete captured sink must remain free of the
credential and metadata map. Unary/stream parity legs must use fresh,
independent stores so a lookup or touch in one leg cannot satisfy the other.

Tests must use fixed non-secret placeholders and conceal the metadata value
before any diagnostic. No assertion may render a request, metadata map, token,
backend error, or complete configuration.
