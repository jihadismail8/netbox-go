Additional scalar rules:

- Manufacturer input stays inside the profile's positive numeric-ID envelope;
  upstream nested dictionary and string lookup forms are not promoted here.
- Slug uses pinned ASCII `^[-a-zA-Z0-9_]+$` grammar and is not generated by the
  API. A Vue suggestion does not alter the wire contract.
- After pinned JSON parsing and DecimalField normalization, `u_height` must be
  a non-negative Decimal(4,1) value and model clean requires the discrete
  half-unit set from `0` through `999.5`. Quoted decimal text retains lexical
  precision, total-digit, and whole-digit checks. Unquoted numeric spelling and
  generic coercion are outside I7. This scalar validation does not close
  positioned-Device transition rules.
- Airflow accepts only `front-to-rear`, `rear-to-front`, `left-to-right`,
  `right-to-left`, `side-to-rear`, `rear-to-side`, `bottom-to-top`,
  `top-to-bottom`, `passive`, and `mixed`. Choice input is not trimmed.
- Airflow SQL `NULL` and stored blank remain distinct durable values, although
  pinned REST serializes both as `null`; a concrete response is a choice
  `{value,label}` envelope. Existing protobuf cannot represent every response
  distinction and earns no T3 claim.
- Combined violations return once in deterministic field order without
  discarding valid sibling-field intent.
- POST retains add permission and PUT/PATCH retain change permission; I7 uses
  authorized principals and does not expand the RBAC matrix.
- Every mutation uses one application-owned PostgreSQL transaction.
  Relationship resolution, authorization, normalization, validation,
  persistence, any existing transition checks, and exactly one typed
  DeviceType object change share that transaction.
- Validation rejection leaves state, timestamp, repository mutation count,
  and object-change count unchanged. Repository or recorder failure rolls all
  durable state and object changes back.
- Scalar fixtures contain no positioned Devices and prove no height-transition,
  instantiation, template, propagation, deletion, or dependent behavior.

Generic coercion, malformed UTF-8, byte-exact framework diagnostics, empty
PATCH, alternate relationship input, and diagnostic multiplicity remain out
of scope. PATCH omission tests include a concrete sibling field.

```json
  "update": {
    "required_fields": [],
    "nullable_fields": ["airflow"],
    "blank_fields": ["part_number", "airflow", "description", "comments"]
  }

```

- The profile validator makes DeviceType operation metadata mandatory and
  rejects missing operations, undeclared or duplicate fields, invalid subsets,
  and request/response conflation.
- Generated OpenAPI replaces `DeviceTypeWrite` with `DeviceTypeCreate`,
  `DeviceTypeReplace`, and `DeviceTypeUpdate`; POST/PUT/PATCH reference their
  matching schema.
- Request Manufacturer is `int64`; response Manufacturer is a non-null
  `ObjectReference`. Request `u_height` is `number`/`double`.
- Request airflow is a nullable scalar string; response airflow is a nullable
  choice envelope. Only airflow, created, and last_updated are nullable in the
  declared response.
- Generated files change only through owned metadata/generator inputs and are
  never hand-edited. Generator source changes require a red resource-neutral
  regression proving a generic defect.

### REST, gRPC, traceability, and Vue

- REST preserves omitted/null/blank/zero/false/concrete states through the
  typed decoder and central error mapper. A handler edit requires a red
  DeviceType decoder regression.
- gRPC optional fields preserve omission, zero, and false. For PATCH, a mask
  path with an absent optional value is explicit-null intent: only airflow
  clears; every non-null scalar rejects. Unknown mask paths fail closed.
- Frozen protobuf carries `u_height` as a string; REST/gRPC parity is semantic
  and does not claim an identical wire type.
- Protobuf cannot encode POST/PUT explicit null or distinguish null from blank
  airflow in every response. No protobuf edit/regeneration or T3 claim is
  authorized; exact REST remains authoritative.
- Traceability adds `unresolved-device-type-scalar-presence` and remaps only
  `operation.dcim.device-type.create`, `.replace`, and `.update` to it.
  `resource.dcim.device-type.contract` and list remain on
  `contradicted-dcim-filter-names`; get/delete, uniqueness, height transition,
  delete/cascade, applicability, verification, consumer, and tier rows remain
  unchanged.
- Vue types DeviceType `created` and `last_updated` as `string | null`, supplies
  create defaults `u_height: 1`, `exclude_from_utilization: false`, and
  `is_full_depth: true`, requires Manufacturer/model/slug, and declares the
  exact airflow choices.
- Vue declares `u_height` min `0`, max `999.9`, and step `0.5`; domain/API
  validation remains authoritative for the valid maximum `999.5`.
- Vue serializes only the ten owned fields, maps Manufacturer selection to a
  numeric ID, preserves null/false/zero/blank/concrete intent, and keeps a
  private normalized edit baseline. An unchanged edit emits `{}` and one dirty
  field emits one delta.
- Field-scoped backend validation reaches the matching control through the
  real DynamicForm contract; Vue does not own relationship validity or RBAC.
