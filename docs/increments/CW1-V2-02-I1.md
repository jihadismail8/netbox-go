## Required observable contract

### Create, replace, and update

| Field         | POST omitted       | PUT omitted    | PATCH omitted | Explicit `null`          | Explicit `""`            |
| ------------- | ------------------ | -------------- | ------------- | ------------------------ | ------------------------ |
| `address`     | required error     | required error | preserve      | reject: may not be null  | reject: may not be blank |
| `status`      | default `active`   | preserve       | preserve      | reject: may not be blank | reject: may not be blank |
| `role`        | persist SQL `NULL` | preserve       | preserve      | persist blank            | persist blank            |
| `dns_name`    | default `""`       | preserve       | preserve      | reject: may not be null  | clear to `""`            |
| `description` | default `""`       | preserve       | preserve      | reject: may not be null  | clear to `""`            |
| `comments`    | default `""`       | preserve       | preserve      | reject: may not be null  | clear to `""`            |

Additional scalar rules:

- maskless IPv4 and IPv6 inputs gain `/32` and `/128` respectively;
- status and role choices do not trim surrounding whitespace before choice
  validation;
- DNS names are trimmed and lowercased on successful persistence;
- description and comments are trimmed;
- REST blank/null validation uses the exact baseline field envelope;
- gRPC uses the same command state and stable application reason, with its
  transport-native status envelope;
- every rejected input leaves the resource row, `last_updated`, assignment,
  and object-change count unchanged; and
- PUT omission preserves optional VRF and assignment state plus `status`,
  `role`, `dns_name`, `description`, and `comments`; `address` remains
  required. Explicit VRF/assignment behavior remains owned by later
  relationship/assignment increments.

### API and Vue contract

- Resource metadata distinguishes response nullability from POST, PUT, and
  PATCH required/null/blank rules.
- Generated OpenAPI uses operation-specific IPAddress request schemas. POST and
  PUT require `address`; PATCH does not. `role` remains nullable and blankable;
  `address`, `status`, `dns_name`, `description`, and `comments` are not
  nullable. Only `role`, `dns_name`, `description`, and `comments` are
  blankable among those scalar strings.
- The IPAddress response keeps `vrf`, `role`, assignment type/ID, and resolved
  assignment nullable. It also preserves the baseline timestamp nullability;
  non-null address/text/display fields are not advertised as nullable.
- Vue retains `role?: IPAddressRole | null`. An untouched field is omitted, a
  cleared Role selection sends `null`, and a selected role sends its scalar
  value. Text fields retain omission versus blank. The form continues to mark
  Address and Status required and Role/text fields optional.
- Vue consumes field-scoped REST validation; it does not invent a second
  business-error taxonomy.
