unchanged.

## Fixed implementation decisions

### Configuration owner

For this increment, the only CORS configuration input is the hand-owned
environment variable:

```text
NETBOX_CORS_ALLOWED_ORIGINS
```

Its value is a comma-separated list of exact HTTP(S) origins. Unset and
explicitly empty values both mean an empty allowlist and therefore no
cross-origin permission.

Do not add `http.allowedOrigins` to either YAML file. Do not edit or regenerate
`internal/config/netbox_go.go`. The current Sponge config generator is outside
the pinned deterministic toolchain, scans multiple YAML variants, and is not
needed for an environment-owned security boundary. Avoiding it is an explicit
scope decision, not deferred design work.

The parser and immutable runtime value belong in new hand-owned
`internal/platform/config/cors.go`. This is the layer-first platform/config
owner required by the architecture; the existing `internal/config` package
remains only the generated YAML plus its narrow legacy override boundary.

Define this shape, with no package-global state:

```go
type HTTPRuntime struct {
	corsAllowedOrigins []string
}

func LoadHTTPRuntimeFromEnvironment() (HTTPRuntime, error)
func (r HTTPRuntime) CORSAllowedOrigins() []string
```

- `LoadHTTPRuntimeFromEnvironment()` reads and validates the environment and
  returns an immutable value. Its unexported parser builds the complete local
  slice before constructing the value.
- `HTTPRuntime.CORSAllowedOrigins()` returns a defensive copy.
- `initial.getConfigFromLocal()` calls the existing
  `config.ApplyEnvironmentOverrides()`, then calls the new loader, and returns
  the value before startup reaches the database.
- `initial.initConfig()` and `initial.InitApp()` return the same value to
  `main`; `main` passes it to `initial.CreateServices()`.
- Every later ownership boundary also copies the slice.
- An unset or empty environment value creates a fresh empty value; no policy is
  retained between calls or processes.
- Do not add a package-global snapshot, singleton, setter, service locator, or
  hidden `init()` registration. Such a shortcut violates ARCH-006 and the
  constructor-injection rule in the coding standards.

### Configuration grammar and normalization

Before trimming or splitting, reject CR, LF, DEL, and every C0 control character
except HTAB. Trim only ASCII space (`SP`, `0x20`) and tab (`HTAB`, `0x09`)
around the complete value and around each comma-delimited element. After that
trim, reject SP or HTAB inside an origin. An empty whole value after this narrow
trim is valid. Once the whole value is non-empty, an empty element is invalid;
for example, `https://a.example,,https://b.example` fails startup.

Each element must parse as exactly:

```text
http://host[:port]
https://host[:port]
```

Apply this deterministic canonicalization before duplicate detection:

1. Lowercase the scheme and DNS hostname.
2. For a literal address, parse with standard-library `net/netip`. Use
   `netip.Addr.String()` as the address spelling so IPv4 is strict and
   equivalent expanded/uppercase IPv6 forms become one compressed lowercase
   value. Reject IPv6 zones and nonstandard IPv4 forms rather than repairing
   them.
3. Store IPv6 literals in bracketed URL form.
4. Accept only canonical unsigned decimal ports from 1 through 65535, with no
   sign or leading zero. Preserve a valid non-default port.
5. Remove `:80` from HTTP and `:443` from HTTPS.
6. For a DNS hostname, accept only ASCII labels containing letters, digits, and
   interior hyphens. Reject empty labels, a leading/trailing hyphen, a trailing
   dot, labels over 63 bytes, and a hostname over 253 bytes. `localhost` and
   ASCII punycode labels are valid. The final DNS label must contain at least
   one ASCII letter. Reject an all-numeric host and legacy numeric/hex/octal
   IPv4-looking forms unless the entire host parses as canonical IPv4 through
   `netip`; they must never fall through to DNS validation.
7. Require the parsed URL path to be empty. A non-empty parsed path, including
   a lone trailing `/`, is invalid rather than silently repaired. The `//`
   delimiter after the scheme is of course not a URL path.

Reject the whole configuration with a narrow error when an element has any of
these properties:

- `*`, a partial wildcard, or a regular expression;
- `null`, `file:`, `ws:`, `wss:`, browser-extension, or another non-HTTP(S)
  scheme;
- missing scheme, missing host, opaque URL form, or more than one serialized
  origin;
- user information, password, path, trailing slash, query, or fragment;
- port zero, a signed or leading-zero port, a nonnumeric port, a port above
  65535, or another malformed port;
- a comma, backslash, invalid host delimiter/syntax, control character, CR/LF,
  internal whitespace, percent-escaped host, IPv6 zone identifier, or
  non-ASCII hostname;
- a canonical duplicate of an earlier entry.

Errors must contain only `NETBOX_CORS_ALLOWED_ORIGINS`, the zero-based element
index, and a stable reason. Never include the raw element, a substring derived
from it, the complete environment value, or the effective configuration in an
error or log; an invalid element can itself contain userinfo or secret-like
material.

The middleware does not repair request origins. It obtains all `Origin` header
values, requires exactly one value, and performs an exact string lookup against
the canonical configured set. A combined/multiple, whitespace-altered,
malformed, or noncanonical request value therefore receives no permission.
Normal browsers serialize HTTP(S) origins canonically.

### Explicit injection path

Use this ownership flow and no service locator or mutable package-global state
anywhere:

```text
initial.getConfigFromLocal
  -> legacy config.ApplyEnvironmentOverrides
  -> runtimeconfig.LoadHTTPRuntimeFromEnvironment
  -> initial.InitApp returns immutable HTTPRuntime before main composition
  -> main passes HTTPRuntime to initial.CreateServices
  -> HTTPRuntime.CORSAllowedOrigins (defensive copy)
  -> server.WithHTTPCORSAllowedOrigins (defensive copy)
  -> server.NewHTTPServer/httpOptions (defensive copy)
  -> canonical router.New (defensive copy into an immutable lookup set)
  -> trusted-origin CORS middleware
```

Make the constructor change compile-visible:

- Add `corsAllowedOrigins []string` to canonical `router.New` and
  `newWithLogger` immediately after `secureCookies` and before the existing
  variadic workflow options.
- Change `initial.InitApp()` to return `runtimeconfig.HTTPRuntime` and thread
  that return through `initConfig()`/`getConfigFromLocal()` without changing
  the established pre-database validation order.
- Change `initial.CreateServices` to accept the immutable runtime value.
- Change `cmd/netbox_go/main.go` to capture the return from `InitApp()` and pass
  it to `CreateServices()`.
- Add `corsAllowedOrigins []string` to `server.httpOptions`.
- Add `server.WithHTTPCORSAllowedOrigins([]string)` and clone its input.
- `initial.CreateServices` is the only production caller that reads the
  immutable value and supplies the HTTP option.
- `server.NewHTTPServer` passes the option value to the canonical router.
- Tests and the REST surface contract pass an explicit empty or test
  allowlist. Do not hide the new dependency in a package global.
- The admin CLI remains unchanged because it starts no HTTP runtime. It must
  still compile; CORS environment validation belongs to the network-process
  startup path.

Do not put CORS in `composition.Core`, a domain/application service, identity
handler, PostgreSQL adapter, gRPC adapter, generated router, or frontend.

### Canonical middleware scope and ordering

Implement a small standard-library plus Gin middleware in new
`internal/adapters/rest/netbox/router/cors.go`. Do not use
`gin-contrib/cors` or Sponge's `middleware.Cors()`.

Install it once on the canonical Gin engine, after recovery and before timeout,
request ID, access logging, rate limiting, tracing, identity, workflows, schema,
health/readiness, and SPA handlers. It applies to the whole canonical engine,
matching the pinned middleware's default URL scope. It does not register an
`OPTIONS` route and never touches the legacy router.

Set a trusted actual request's allow headers before invoking downstream
handlers so authentication failures and recovered error responses remain
readable to the trusted browser. Preserve downstream status, body, and existing
headers.

### Fixed wire contract

The declared method list is exactly this order and spelling:

```text
DELETE, GET, OPTIONS, PATCH, POST, PUT
```

The declared request-header list is exactly this order and lowercase wire
spelling, matching the pinned NetBox dependency:

```text
accept, authorization, content-type, user-agent, x-csrftoken, x-requested-with
```

Do not add `x-request-id`, wildcard headers, or any header inferred from an
incoming request. Request-header comparisons performed by browsers are
case-insensitive; the response remains the fixed string above.

The preflight cache age is fixed to the pinned default:

```text
Access-Control-Max-Age: 86400
```

`Vary` is merged case-insensitively and without deleting existing values. The
fixed response does not vary by requested method or requested headers, so this
increment adds only `Origin`, matching the pinned middleware. Do not duplicate
an existing `Origin` token. If an existing response already contains
`Vary: *`, preserve the single wildcard semantic and do not append `Origin`.

The response matrix is normative:

| Request class                                                                                                                                             | Required result                                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Actual request, one exact trusted `Origin`                                                                                                                | Preserve downstream status/body. Add exact `Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials: true`, and merged `Vary: Origin`.                                                                                                                                     |
| Actual request, no `Origin`                                                                                                                               | Preserve downstream status/body. Add/merge `Vary: Origin`; emit no `Access-Control-Allow-*` permission.                                                                                                                                                                            |
| Actual request, malformed, multiple, `null`, or untrusted `Origin`                                                                                        | Preserve downstream status/body. Add/merge `Vary: Origin`; emit no `Access-Control-Allow-*` permission. Do not replace the downstream result with 403.                                                                                                                             |
| `OPTIONS` with an `Access-Control-Request-Method` field present, even when its value is empty, and one exact trusted `Origin`                             | Stop before auth/handlers. Return 200, an empty body, `Content-Length: 0`, exact origin, credentials `true`, the fixed allow-method/header lists, max-age `86400`, and merged `Vary: Origin`.                                                                                      |
| `OPTIONS` with an `Access-Control-Request-Method` field present, even when its value is empty, and no, malformed, multiple, `null`, or untrusted `Origin` | Stop before auth/handlers. Return 200, an empty body, `Content-Length: 0`, and merged `Vary: Origin`; emit no `Access-Control-Allow-*` permission.                                                                                                                                 |
| `OPTIONS` without an `Access-Control-Request-Method` field and one exact trusted `Origin`                                                                 | It is not a preflight. Continue through the existing router and preserve its status/body. Continue through the existing router and preserve its status/body. Add/merge `Vary: Origin`, emit no `Access-Control-Allow-*` permission, and do not register an OPTIONS route.                                                                             |

For a trusted preflight requesting an unsupported method such as `TRACE` or an
unsupported header, return the same fixed trusted preflight response. Never
reflect the requested value. Because the requested method/header is absent from
the fixed allowlist, the browser denies that permission. This deliberately
matches the pinned middleware instead of inventing a server-side 403/204
policy.

No response may emit any of the following:

- `Access-Control-Allow-Origin: *`;
- a reflected unconfigured origin;
- `Access-Control-Allow-Headers: *`;
- `Access-Control-Expose-Headers`;
- `Access-Control-Allow-Private-Network`;
- a regex or suffix-based origin match; or
- CORS headers copied from request-provided method/header lists.

### CSRF and credentials

CORS grants browser visibility; they do not authenticate a principal and do
not authorize or validate a mutation.

- Preflight terminates before authentication and requires no session or CSRF
  token.
- A trusted-origin cookie-authenticated unsafe request still requires the
  existing matching CSRF cookie/header pair.
- Missing or wrong CSRF remains 403, with trusted CORS headers so the permitted
  browser can read the denial.
- A matching CSRF request reaches the same existing handler outcome.
- Token authentication keeps its existing CSRF-independent rule and existing
  read/write restrictions.
- Do not change cookie names, `Secure`, `HttpOnly`, path, lifetime, rotation,
  or `SameSite=Lax` behavior. In particular, this goal does not authorize
  third-party-site cookie support.
- Do not change login/token throttling or log request origins, authorization,
  cookies, CSRF material, or complete CORS configuration.
