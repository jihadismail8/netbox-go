## Entry defect

Production startup already appears to implement missing-table-only bootstrap:
it checks `HasTable`, skips an existing table, and invokes relationship-disabled
`AutoMigrate` plus declared foreign keys and indexes only for an absent table.
The current tests do not prove the complete contract:

- the registry unit test checks 198 entries but not their exact order;
- the fresh-PostgreSQL test spot-checks only nine physical tables;
- the malformed-existing-table test uses a two-entry synthetic registry;
- private-row PostgreSQL tests verify selected columns or checks, not every
  private table, column, constraint, index, and foreign-key action;
- content-type uniqueness has no retained real-PostgreSQL proof; and
- no catalog snapshot proves a correct existing startup table remains
  untouched.

This is therefore a proof-first increment. Production behavior is not
pre-authorized for change.

## Required observable contract

### Registry and bootstrap policy

- The startup registry has one exact deterministic sequence of all current
  198 entries. The test must compare the complete ordered identity/table
  sequence against a hand-owned expectation. The number 198 is a guard only;
  it is not capability evidence by itself.
- On an empty owned PostgreSQL database, every registry entry is visited in
  exact order and every expected physical table exists afterward.
- A second run reports every entry as existing in the same order and performs
  no schema mutation; a canonical whole-registry semantic catalog fingerprint
  is identical before and after the rerun.
- In a non-empty database, an absent registry table is created normally.
- A correct existing registry table is skipped and its relevant catalog shape
  is identical before and after bootstrap.
- A deliberately malformed existing registry table is also skipped. Bootstrap
  must not add, remove, inspect for repair, or drift-correct its columns,
  constraints, indexes, or foreign keys.
- `AutoMigrate`, foreign-key creation, and index creation occur only on the
  path reached after table absence is confirmed. Existing tables never enter
  that path.
- Determinism covers registry/table visitation and the final semantic catalog.
  It does not invent an ordering guarantee for per-table FK or index DDL built
  from Go maps.

### Private schema contract

Real PostgreSQL must prove the declared contract for all current private typed
tables: eight identity tables, ten DCIM tables, three IPAM tables, and the
object-change table. Expectations are explicit and reviewable, covering as
applicable:

- physical table and column names;
- PostgreSQL data type, nullability, default, and primary-key ownership;
- check, unique, and partial-index predicates;
- ordinary and unique indexes;
- foreign-key target columns and `ON UPDATE`/`ON DELETE` actions; and
- the unique natural key on Django content type `(app_label, model)`.

The current hand-owned expectation contains 22 primary keys, 24 foreign keys
(all `ON UPDATE CASCADE`; six identity join-table edges `ON DELETE CASCADE`
and the other 18 `ON DELETE RESTRICT`), one named IP-assignment check, 22
non-primary unique indexes, and 55 declared non-unique secondary indexes.
Expression and partial-index expressions/predicates are semantic fields, not
mere index-existence checks.

Catalog assertions may normalize PostgreSQL-assigned constraint/index names
where naming is not part of the contract, but must not discard semantic
differences. They must not treat an unexpected extra private column,
constraint, index, or foreign key as success.

### Test isolation

- PostgreSQL tests use one explicitly owned disposable database and isolate
  their schemas/tables so reruns are deterministic.
- Tests own cleanup for objects they create and never alter another developer
  database or table.
- Tests skip only when `NETBOX_TEST_POSTGRES_DSN` is absent. Every retained
  V3-02 real-PostgreSQL command supplies it and treats a skip as failure.
- Logs, reports, command transcripts, and evidence never contain the DSN or
  reusable credentials.
- No arbitrary sleep, execution-order dependence, SQLite substitution, or
  count-only shortcut is accepted.
